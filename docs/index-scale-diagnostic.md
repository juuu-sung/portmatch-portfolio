# 고정 모델·훈련 사전 80%/100% 진단

> 공개용 정리본: 실제 선박별 입력·정답·예측·점수와 행 식별자는 제외했다. 아래 성능표는 실제 실험의 집계 수치이며, 오류의 원리는 별도의 [가상 예시](fictional-examples.md)로 설명한다.

2026-10-28. **fold0·2의 실제 공개 데이터 전체 비교와 분석을 완료했습니다.** 4,902행·49,020개 저장 예측에서100% 사전은 원본+0.3423%p, 두 GT 결측−0.6846%p, 국제GT×1.25 −0.3423%p이며 fold2는 모든 예측이 같았습니다. 정답 후보 획득·손실은0건입니다. 80% 사전을 채택하지 않고 현재 최고 제출인 robust·86개·GT 결측 증강0.5 fold0를 유지합니다. [결과·선박별 분석과 다음 실험](experiments/index-scale-fold02.md). 이 문서의 명령은 완료한 진단의 재현 기록입니다.

이번 저장 산출물 감사5,057개를 모두 통과했습니다. 100% 원본4,902행의 기존 저장 예측 일치, 분할·80% 선박 선택·검증 제외, 산출물·보호 파일·코드 해시와 실제 두 모델 가중치·훈련 자산을 확인했습니다. 구현 당시 전체307개 테스트와 기존 모델·ZIP 보존 검사 기록은 유지하며, 이번에는 재학습이나 테스트 재실행을 하지 않았습니다.

전체훈련 후속 제출은 사용자 보고0.8324345055로 기존0.8424607623보다1.00262568%p 낮았습니다. 두 제출 사이 순위 모델 가중치와 추론 사전이 동시에 달라졌으므로 우선 가중치를 고정한 상태에서 훈련 사전 범위에 얼마나 민감한지 확인합니다. [제출 기록과 조사 근거](full-training.md#public-결과와-다음-진단).

## 무엇을 고정하고 바꾸는가

각 fold의 기존 선박 분할에서 훈련 집합을T, 검증 집합을V라고 합니다. T의 선박 ID와 고정 seed를 해시해 정렬하고 `floor(0.8 × T의 선박 수)`척을 선택합니다. 선택된 선박의 **원본 행 전체**를 모은 집합이M입니다. 행80%를 뽑거나 선박의 일부 기록을 떼지 않습니다. seed는20261027이며 성능·검증 정답을 보고 부분집합을 고르지 않습니다.

| 항목 | `index_80` | `index_100` |
|---|---|---|
| 사전 범위 | M: T 안에서 고른80% 선박의 원본 전체 | T: 해당 fold 훈련 원본 전체 |
| 호출부호·정규화 이름 조회 | M에서 생성 | 저장된 T 사전, T에서 재구성한 통계와 대조 |
| 별칭·이름 검색 TF-IDF | 고정 카탈로그 + M의 별칭 | 고정 카탈로그 + T의 별칭 |
| 국적·선종 통계 | M에서 생성 | T에서 생성된 저장 통계 |
| 순위 모델 | 두 사전이 동일한 기존 모델 객체와86개 특징 선택을 공유 | 동일 |
| 평가 입력 | 같은 V 행과 같은 입력 변형 | 동일 |

두 사전 모두 V의 행·선박을 제외합니다. 고정 카탈로그는 대회에서 제공한 검색 대상이며 양쪽이 같은 것을 사용합니다. 검증 정답은 검색·특징·모델 점수를 구한 뒤 채점과 진단용 후보 선택에만 사용합니다. 추론 중 조회 사전이나 범주 통계를 갱신하지 않습니다.

각 fold의 `artifacts/ranker_robust_gt_missing_token_phonetic_foldN`을 읽습니다. robust 검색,86개 특징, 원본 질량0.5,300회·6스레드 등 기존 설정을 검사하고 가중치는 학습하거나 수정하지 않습니다.80%와100%는 명령의 고정 비교 범위이며 비율 탐색 옵션은 없습니다. 기존 특징 캐시를 다시 만들거나 기존 모델·`index.joblib`을 덮어쓰지 않고, 새 배포 모델이나 ZIP도 생성하지 않습니다.

## VS Code PowerShell 실행

아래는 **완료한 실행 명령**입니다. 같은 출력 폴더에 다시 실행하지 않습니다. fold0을 완료한 뒤 fold2를 실행하며 작은 표본 제한을 지정하지 않아 각 fold의 **검증 전체 행 ×5개 조건 ×2개 사전**을 추론했습니다. 실제 후보 검색과 특징 계산을 다시 수행하는 경로입니다.

```powershell
cd C:\dacon\port

foreach ($fold in @(0, 2)) {
    .\.venv\Scripts\python.exe -m portmatch compare-index-scale --model "artifacts/ranker_robust_gt_missing_token_phonetic_fold$fold" --fold $fold --subset-seed 20261027 --output "runs/compare_index_scale_fold$fold"
    if ($LASTEXITCODE -ne 0) { throw "fold$fold 사전 범위 진단 실패" }
}
```

`--fold`는 저장 모델의 외부 fold와 일치해야 합니다. 입력은 기본 `work/data/train.csv`와 `work/data/vessel_catalog.csv`이며 다른 위치를 사용하려면 `--train`·`--catalog`를 지정합니다. 파일 내용은 저장 모델의 원본 해시와 같아야 합니다.

출력은 **새 폴더 또는 빈 폴더**여야 합니다. 완료된 fold를 같은 경로에 다시 실행하지 않습니다. 중단된 실행은 자동 이어쓰기를 지원하지 않으므로 재시도할 때 `runs/compare_index_scale_fold0_retry1`처럼 새 출력명을 사용합니다. 기존 결과를 삭제해 재사용할 필요는 없습니다.

선택적으로 먼저64행의 동작만 확인하려면 별도 폴더를 사용합니다. 본 실행은 위 명령처럼 `--max-queries`를 빼야 합니다.

```powershell
.\.venv\Scripts\python.exe -m portmatch compare-index-scale --model artifacts/ranker_robust_gt_missing_token_phonetic_fold0 --fold 0 --subset-seed 20261027 --max-queries 64 --output runs/compare_index_scale_smoke_fold0
if ($LASTEXITCODE -ne 0) { throw "fold0 사전 범위 표본 진단 실패" }
```

표본 제한은 검증 질의 수만 줄이며80% 사전 구성은 본 실행과 같습니다. `coverage.diagnostic_sample`과 실제 포함 행·선박·언어 수를 확인합니다. 표본에서 한 언어가 빠지면 한글0.7·비한글0.3 가중 지표는 계산하지 않으며 `null`로 기록합니다. 표본 점수를 전체 fold 결과처럼 해석하지 않습니다.

## 입력 조건과 비교 지표

기본 다섯 조건은 `original`(원본), `both_gt_missing`(두 GT 결측), `international_gt_missing`(국제 GT 결측), `gross_gt_missing`(일반 GT 결측), `international_gt_x1_25`(양수인 국제 GT를1.25배)입니다. 이미 결측이거나 유효한 양수가 아닌 값은 배율로 새 값을 만들지 않으며 실제 변경 행 수도 기록합니다. 원본 입력 파일은 보존하고 같은 변형 입력을 양쪽 사전에 줍니다.

모든 변화량은 **동일한 입력 조건의 `index_100 − index_80`**입니다. 기존86개 모델이나 원본 입력을 분모로 쓰는 비교가 아닙니다.

- 정확도: 전체·한글·비한글 Top-1, 언어별 정답/분모, 한글0.7+비한글0.3 가중 Top-1.
- 후보: 언어별 후보 재현율과 가중 후보 재현율, 최종 순위의 Recall@5/10/50/100/200, 후보 수 평균·중앙값·95백분위·최대.
- 오답: 개선·신규 오답의 행 수와 선박 수, 정답 후보 유입/누락, 후보 집합 변화, 양쪽 모두 오답인 상태에서 예측이 달라진 행. 오답 원인은 후보 누락과 후보 안의 순위 오류로 나눕니다.
- 시간: 후보 검색·특징 계산·순위 계산·합계의 총 시간과 행당 분포. 각 행·조건에서 실행 순서를 번갈아 배치해 한 사전이 계속 먼저 실행되는 편향을 줄입니다.

행별 추론 시간에는 모델·사전 초기화, 이름 특징 준비, warmup, 진단용 특징 추출·보고서 저장 시간을 넣지 않습니다. 초기화와 warmup은 별도로 기록합니다. 단일 로컬 실행의 시간 차이는 부하와 캐시 영향을 받을 수 있으며 서버 추론 속도나 대회 시간 제한 충족을 보장하지 않습니다.

## 결과 파일과 완료 확인

| 파일 | 내용 |
|---|---|
| `summary.json` | 범위·해시·분할 증명, 지표·변화량, 초기화/실행 시간, 저장 예측 일치와 보존 검사, 완료 상태 |
| `predictions.csv` | 모든 행·조건·사전의 예측, 정답 순위, 후보 수/집합 해시, 점수·시간과1위/정답의 검색 특징 |
| `row_changes.csv` | 같은 행·조건의80%/100% 쌍, 개선/신규/오답 유지 등 상태, 후보 유입/누락, 점수·특징·시간 차이 |
| `vessel_changes.csv` | 조건·정답 선박·언어별 집계와 개선/신규 오답, 후보 변화 |
| `changed_candidate_features.csv` | 예측 변경 행에서 정답과 양쪽1위 후보를 **동일 선박 ID**로 맞춘 점수·검색/범주 특징 |
| `partitions.csv` | 원본 행의 외부 훈련/검증 및80% 사전 포함 여부 |
| `report.md` | 한국어 요약 표, 오답 변화와 해석 한계 |

진단 특징에는 이름·음차 검색 점수/순위, 조회 지원도/순도, 국적·선종 확률과 lift, 검색 채널 수가 포함됩니다. `row_changes.csv`의 양쪽 `top_` 열은 예측이 바뀌면 서로 다른 선박을 뜻합니다. 같은 후보의 변화는 `changed_candidate_features.csv`를 사용합니다. 한쪽에 후보가 없으면 `present=false`와 빈 점수/특징으로 남기며 정답을 후보에 강제로 추가하지 않습니다.

정상 완료는 `summary.json`의 다음 검사를 함께 확인합니다.

- `complete=true`, `weights_unchanged=true`, `training_assets_unchanged=true`, `protected_files_unchanged=true`.
- `ranker_shared_by_both_indexes=true`: 두 사전이 동일한 가중치와 특징 선택을 공유.
- `parity`:100% 사전의 원본 예측이 기존 `validation_predictions.csv`와 일치. 본 실행은 검증 전체를, 표본 실행은 선택 행을 비교합니다.
- `coverage`: 기대한 fold·행·선박·언어 수와 전체/표본 여부. 기본 본 실행에서는 `diagnostic_sample=false`.
- `proof`와 출처: V 제외, M⊂T, 원본·저장 모델·코드 해시와 설정 일치. 시작과 종료에 보호 파일을 대조합니다.

중복 행, 누락된80%/100% 쌍, 행의 정답·언어·이름 불일치, 잘못된 순위/후보 수는 보고서 생성을 거부합니다. 후보 집합 자체가 달라지는 것은 이번 실험의 관찰 대상이므로 양쪽 후보의 동일성을 요구하지 않습니다. 중간 산출물이나 `complete=false`는 완료 결과로 분석하지 않습니다.

## 결과를 읽는 기준과 한계

먼저100% 원본이 저장 예측과 일치하는지와 보존 검사를 확인합니다. 이후 fold0·2 각각 원본과 톤수 변형의 정확도, 한글 후보 유입/누락, 같은 후보의 검색 점수·순위·범주 특징 변화가 반복되는지 봅니다. 전체 정답 수와 언어 가중 점수는 다를 수 있으므로 언어별 분자·분모와 선박별 신규 오답을 함께 판단합니다. 두 fold를 합칠 때도 fold 점수의 단순 평균 대신 언어별 분자·분모를 합산합니다.

이 모델은 원래 T 전체로 학습됐습니다.80% 사전은 그 모델에 더 작은 자산을 연결한 인위적 진단이며80% 데이터로 재학습한 모델의 성능이 아닙니다. V의 정답 선박은 모두 T 밖이므로 사전 확장으로 새로 학습에 포함된 선박의 호출부호·이름 조회 이득을 측정하지 못합니다.100% 사전이 나빠지더라도 실제 full-vs-fold0 Public 하락의 원인으로 곧바로 확정하거나80% 사전을 제출용으로 채택하지 않습니다.
