- 원본 파일 해시, 전체 원본 수·ID·내용의 해시, 내부 분할·OOF 로그, 원본별 질량, 원본 전체로 만든 최종 사전·범주 통계의 일치를 확인합니다.
- `full_training_pair_proof`는 원래70개 특징·후보·라벨·그룹·순서·질량 배열을 묶습니다. 생성 뒤 값이 바뀌면 변환·학습을 거부하고,87열 파생에서도 보존된70열과 나머지 배열을 재검사합니다.
- 기존 외부 fold 학습·평가·재가중치 명령은 전체훈련 캐시를 거부합니다. 전체훈련 경로는0.5와 기본 학습 설정만 허용하며, 명시적인 부분 실행(`--max-train-queries`)은 진단용으로 표시하고 제출 패키징을 거부합니다.
- 패키징은 `--allow-full`을 명시해야 합니다. 원본 전체 검증·특징 변환 증명·모델/인덱스/코드 해시를 확인하고, 원본 CSV·특징 NPZ·행별 라벨·로컬 경로를 ZIP에 넣지 않습니다. 고정된 학습 사전은 추론 자산으로 포함합니다.

## 완료한 VS Code PowerShell 실행 기록

아래5단계는 **모두 완료한 실행 기록**이며 같은 출력 폴더에 다시 실행하지 않습니다. 특징 생성→이름 특징 변환→학습→ZIP→실제 검증의 재현 순서를 보존합니다. 새 환경에서 재현할 때도 기존 fold별0.5·0.75 폴더를 사용하거나 덮어쓰지 않습니다. 특히 마지막 검증은 전체 공개 입력의 직접 추론과 ZIP 원본·역순 실행을 포함하므로 시간이 걸립니다.

```powershell
cd C:\dacon\port

.\.venv\Scripts\python.exe -m portmatch prepare-full-ranker --output runs/ranker_data_robust_gt_missing_full
if ($LASTEXITCODE -ne 0) { throw "전체 OOF 특징 생성 실패" }

.\.venv\Scripts\python.exe -m portmatch transform-ranker-cache --transform token-phonetic --data runs/ranker_data_robust_gt_missing_full --output runs/ranker_data_robust_gt_missing_token_phonetic_full
if ($LASTEXITCODE -ne 0) { throw "이름 특징 변환 실패" }

.\.venv\Scripts\python.exe -m portmatch train-full-ranker --data runs/ranker_data_robust_gt_missing_token_phonetic_full --output artifacts/ranker_robust_gt_missing_token_phonetic_full --rounds 300 --threads 6
if ($LASTEXITCODE -ne 0) { throw "전체 모델 학습 실패" }

.\.venv\Scripts\python.exe -m portmatch.submission_package --model artifacts/ranker_robust_gt_missing_token_phonetic_full --output submissions/robust_gt_missing_full/submit.zip --allow-full
if ($LASTEXITCODE -ne 0) { throw "전체 모델 ZIP 생성 실패" }

.\.venv\Scripts\python.exe scripts/verify_full_submission.py --zip submissions/robust_gt_missing_full/submit.zip --reference-model artifacts/ranker_robust_gt_missing_token_phonetic_full --output runs/verify_robust_gt_missing_full --timeout 7200
if ($LASTEXITCODE -ne 0) { throw "전체 모델 ZIP 검증 실패" }
```

완료한 단계는 같은 출력 경로에 재실행하지 않고 다음 단계부터 실행합니다. 중단된 출력 폴더의 자동 이어쓰기는 지원하지 않습니다. 중단된 단계만 재시도할 때는 새 출력 이름을 쓰고 후속 입력 경로도 함께 바꿉니다. 기존 캐시와 원본 파일은 변환·학습·패키징 때 출처 검사에 필요하므로 유지합니다. `train-full-ranker --train ... --catalog ...`로 원본 위치를 바꿀 수 있으나 파일 내용 해시는 같아야 합니다.

`--timeout 7200`은 ZIP 검증의 **각 프로세스당 로컬 대기 상한**입니다. 대회 허용 시간이나 예상 추론 시간이 아닙니다. 실제 시간은 생성된 검증 보고서를 확인합니다. 제출은 이 명령에 포함되지 않습니다.

## 생성 결과와 완료 확인

검증 스크립트는 학습에 사용한 공개 행을 **입출력·행별 독립성 확인용**으로 사용합니다. 원본 전체·역순·언어별 최대32행 부분집합·단독1행·두 GT 결측 부분집합·국제 GT×1.25 부분집합을 각각 새로운 프로세스로 실행합니다. 같은 입력의 저장 모델 직접 예측과 ZIP 예측을 비교하고, 입력 순서·배치가 달라도 같은 행의 예측이 같아야 합니다. 변형 입력의 예측이 원본 예측과 항상 같아야 한다는 요구는 하지 않습니다.

보고서에는 입력/출력 무결성, 카탈로그 ID 유효성, 실제 프로세스 시간·메모리, ZIP/모델 해시를 기록합니다. `accuracy_evaluated=false`, `probe_rows_overlap_training=true`, `upload_performed=false`는 이 로컬 검증의 범위를 나타냅니다. 후속 사용자의 수동 제출 보고와 구분하며 실제 로컬 추론 시간은 위 표에 보존합니다.

## 구현 검증 근거

합성24행·12척으로 내부 OOF 생성→87열 변환→300회·6스레드 LightGBM→모델 저장/복원→ZIP 생성→6조건 실제 프로세스 실행을 확인했습니다. 원본·파생 특징 변조, 다른 설정·출처·범위, 제한된 진단 캐시, 잘못된 검증 성능 표시는 거부합니다. 기존 모델을 유지하기 위해 해시로 보호하는17개 소스 파일을 이전 커밋과 바이트 단위로 대조했고, 기존38개 native 모델 메타데이터/해시와 두 제출 모델의 추론 객체 로딩, 기존 두 ZIP 해시 보존을 확인했습니다.

구현 당시 전체 회귀 **281개 테스트를 통과**했습니다(신규31개 포함,65.30초). 이번 결과 확인에서는 이 테스트를 다시 실행하지 않았습니다. 테스트 임시 파일은 작업 폴더 아래에 생성했습니다. 합성 검증의 시간은 실제 대회 데이터 모델의 추론 시간으로 사용하지 않습니다.
