## 네 조합과 고정 조건

| 기호 | 실행 이름 | 검색 사전 | 국적·선종 통계 |
|---|---|---:|---:|
| A | `search80_category80` | 80% | 80% |
| B | `search80_category100` | 80% | 100% |
| C | `search100_category80` | 100% | 80% |
| D | `search100_category100` | 100% | 100% |

검색 사전은 호출부호·정규화 이름 조회, 별칭·TF-IDF와 검색 채널 전체입니다. 국적·선종 통계는 확률/lift4열만 덮는 것이 아니라 **`CategoryCompatibility` 모델 전체**이며16개 범주 특징을 생성합니다. 네 조합은 동일한 모델 가중치·특징 선택·카탈로그를 공유합니다. 기존 파이프라인과 특징 생성기를 직접 수정하지 않고 각 조합의 독립된 연결 객체를 만듭니다.

기존 외부 훈련T/검증V와 seed20261022를 그대로 사용합니다. T 안에서 subset seed20261027로 선박 ID를 해시해 정렬한 뒤 `floor(0.8 × 훈련 선박 수)`척의 원본 행 전체를80% 집합M으로 선택합니다. M과T에서 만든 검색·범주 자산은 모두 V의 행·선박을 제외합니다. 비율은 선박 수 기준이며 행 수가 정확히80%라는 뜻은 아닙니다. 검증 정답은 검색·특징·모델 점수 산출 후 채점·진단용 후보 선택에만 사용합니다.

모델은 기존 `artifacts/ranker_robust_gt_missing_token_phonetic_foldN`의 robust·86개·원본 질량0.5·300회·6스레드 설정입니다. 기존 특징 캐시 생성·재학습·배포 모델 저장·제출 ZIP 생성은 필요하지 않습니다. 검색 사전M 구성과 네 조합의 비교 추론만 새로 수행합니다.

## 완료한 VS Code PowerShell 실행 기록

아래 명령은 **완료한 fold0·2의 재현 기록**이며 같은 출력 폴더에 재실행하지 않습니다. 각 fold의 **검증 전체 행 ×5개 입력 조건 ×4개 조합**을 계산하고 동일 후보의86개 특징을 저장했습니다. 직전 완료 결과를 `--reference`로 지정해 A·D가 이전80%·100% 비교를 재현하는지도 검사하는 경로입니다. 이 기존 CLI는 fold0·2로 유지합니다. 후속 fold1·3·4도 별도 [검색100% 고정 C/D 비교 명령](category-scope-diagnostic.md)으로 실행·분석을 완료했습니다.

```powershell
cd C:\dacon\port

foreach ($fold in @(0, 2)) {
    .\.venv\Scripts\python.exe -m portmatch compare-index-factorial --model "artifacts/ranker_robust_gt_missing_token_phonetic_fold$fold" --reference "runs/compare_index_scale_fold$fold" --fold $fold --subset-seed 20261027 --output "runs/compare_index_factorial_fold$fold"
    if ($LASTEXITCODE -ne 0) { throw "fold$fold 검색·범주 2x2 진단 실패" }
}
```

`--reference`는 같은 fold·모델·원본·부분집합 seed로 완료한 **전체 검증5조건의 `compare-index-scale` 폴더**여야 합니다. 표본 결과를 기준으로 사용하지 않습니다. 기존 파일 해시·코드·학습 자산·가중치·검증 ID를 확인하며 기준 폴더의 파일을 변경하지 않습니다. 현재 완료한 `runs/compare_index_scale_fold0`와 `runs/compare_index_scale_fold2`를 그대로 사용합니다.

출력은 **새 폴더 또는 빈 폴더**여야 합니다. 중단 후 자동 이어쓰기는 지원하지 않으므로 `runs/compare_index_factorial_fold0_retry1`처럼 새 출력명을 사용합니다. 기존 결과를 삭제하거나 덮어쓰지 않습니다. 원본 입력은 기본 `work/data/train.csv`, `work/data/vessel_catalog.csv`이며 경로를 바꿔도 저장 모델의 원본 내용 해시와 같아야 합니다.

아래64행 표본 명령은 향후 구현 점검용 사용법입니다. 완료된 전체 비교를 다시 실행할 필요는 없습니다. 재현할 때도 기준은 위의 완료한 전체 결과이며 별도 새 출력 폴더를 사용합니다. 전체 본 실행에서는 `--max-queries`를 빼야 합니다.

```powershell
.\.venv\Scripts\python.exe -m portmatch compare-index-factorial --model artifacts/ranker_robust_gt_missing_token_phonetic_fold0 --reference runs/compare_index_scale_fold0 --fold 0 --subset-seed 20261027 --max-queries 64 --output runs/compare_index_factorial_smoke_fold0
if ($LASTEXITCODE -ne 0) { throw "fold0 검색·범주 2x2 표본 진단 실패" }
```

표본 제한은 검증 질의 수만 줄이고 사전 범위는 본 실행과 같습니다. 한 언어가 표본에 없으면 가중 정확도·재현율과 해당 가중 변화량은 `null`이며 표본을 전체 fold 성능으로 해석하지 않습니다.

## 입력 조건·대조·상호작용

다섯 입력은 원본, 두 GT 결측, 국제 GT 결측, 일반 GT 결측, 양수 국제 GT ×1.25입니다. 원본 파일을 보존하고 같은 변형 입력을 네 조합에 전달합니다. 각 조합의 전체·한글·비한글 Top-1, 후보 재현율, Recall@5/10/50/100/200, 후보 수와 구간별 시간을 기록합니다. 가중 점수는 한글70%+비한글30%입니다.

| 대조 이름 | 변화량 | 확인하는 효과 |
|---|---|---|
| `category_at_search80` | B−A | 검색80을 고정한 범주80→100 |
| `category_at_search100` | D−C | 검색100을 고정한 범주80→100 |
| `search_at_category80` | C−A | 범주80을 고정한 검색80→100 |
| `search_at_category100` | D−B | 범주100을 고정한 검색80→100 |
| `diagonal` | D−A | 기존 검색·범주 동시80→100 |

각 대조마다 개선·신규 오답·오답 유지·후보 유입/누락을 행·선박·언어별로 집계합니다. 상호작용은 **`(D−C)−(B−A)`**로, 검색 규모에 따라 범주 효과가 얼마나 달라지는지 보여주는 산술 차이입니다. 정확도·재현율은%p, 후보 수는 개수, 시간은 초 단위로 계산하며 시간 비율끼리 빼지 않습니다. 상호작용을 통계적 유의성이나 Public 점수 하락의 증명으로 해석하지 않습니다. 서로 다른 입력5조건을 한 점수로 평균내지 않습니다.

## 동일 후보의 전체86개 특징

**예측이 달라진 행뿐 아니라 모든 질의·조건**에서 정답과 네 조합의1위 후보를 합친 선박 ID 집합을 만들고, 그 후보들을 네 조합에 정렬합니다. 모든 검색 후보의86열을 파일로 내보내는 것은 아니며, 출력 대상 후보를 제한해 파일을 순차 저장합니다. 선택된 후보의86개 값은 실제 순위 모델에 입력한 `float32` 배열입니다. 톤수 순위를 포함한87열 원본이나 일부 진단 특징만 저장한 값이 아닙니다.

후보가 없으면 `present=false`와 빈 점수·특징으로 남기며 정답을 강제로 삽입하지 않습니다. 후보가 존재하지만 특정 특징이 NaN이면 해당 값은 비어 있습니다. `feature_changes.csv`의 `reference_is_nan`·`experiment_is_nan`으로 유한값↔NaN 전이를 구분합니다. 양쪽 NaN은 변경으로 세지 않고 NaN 전이의 수치 차이는 비워 둡니다.

| 파일 | 내용 |
|---|---|
| `summary.json` | 네 조합 지표·5대조·상호작용, 특징 목록·dtype, 분할/자산 증명, 기존 결과 일치·불변 검사, 완료 상태와 산출물 해시 |
| `predictions.csv` | 모든 질의·조건·조합의 예측·정답 순위·후보 수/집합 해시·점수·시간과 기존11개 진단 특징 |
| `row_changes.csv` | 5대조별 행 비교, 개선/신규/오답 유지, 후보·점수·시간 변화 |
| `vessel_changes.csv` | 대조·조건·정답 선박·언어별 집계 |

## 실행 중 검증과 완료 확인

파일 출력 대상으로 선택한 후보뿐 아니라 **그 질의에서 검색한 모든 후보**를 대상으로 분리 조건을 검사합니다.

- 같은 검색 사전의 A/B와 C/D: 후보 집합·수·정답 포함 여부가 같고, 모든 후보의 **비범주70개 특징**이 같아야 합니다.
- 같은 범주 통계의 A/C와 B/D: 양쪽 공통 후보의 **범주16개 특징**이 같아야 합니다.
- 파이프라인·특징 생성기 연결, 검색 객체·TF-IDF·조회·범주·카탈로그 특징 자산과 모델 가중치를 시작/종료에 대조합니다. 모델·원본·기준 결과 파일도 보존돼야 합니다.
- A와D는 다섯 조건에서 기존 기준의80%·100% 예측 ID·정답 순위·후보 수/집합·점수·저장된 진단 특징을 재현해야 합니다. 시간은 이전 실행과 같은 값일 수 없어 일치 조건에 넣지 않습니다. D의 원본은 모델의 기존 `validation_predictions.csv`와도 대조합니다.

정상 완료는 `summary.json`의 `complete=true`, `weights_unchanged=true`, `training_assets_unchanged=true`, `protected_files_unchanged=true`, `reference_files_unchanged=true`, `ranker_shared_by_all_runners=true`를 확인합니다. `feature_isolation.verified`, `same_search_candidate_invariance_verified`, `parity.reference_diagonals.verified`와 `parity.saved_original.all_selected_original_predictions_match`도 통과해야 합니다. 기본 본 실행은 `coverage.diagnostic_sample=false`이며 모든 검증 행을 포함합니다. 중간 파일이나 `complete=false`는 완료 결과가 아닙니다.

행별 추론 시간은 검색·특징 계산·순위 계산을 포함하고 초기화·warmup·분리 검사·특징 추출/저장은 제외합니다. 네 조합의 실행 순서를 질의·조건마다 순환합니다. 초기화는 별도 기록하며 `total_seconds`는 최종 보고서 저장 전까지의 경과 시간입니다. 단일 로컬 실행의 캐시·부하 영향을 고려해야 하며 서버 속도나 대회 시간 제한을 판정하는 실행이 아닙니다.
