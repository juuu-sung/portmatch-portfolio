## 다음 재학습과 판단 기준

아래는 최초 안내했던 VS Code PowerShell 전체 실행 기록입니다. **2026-10-24 특징 생성·변환·학습은 완료했습니다.** 현재는 다음 절의 비교 명령만 실행합니다. 완료 단계를 반복하거나 중단·완료 폴더를 덮어쓰지 않습니다.

```powershell
cd C:\dacon\port

& {
    .\.venv\Scripts\python.exe -m portmatch prepare-ranker --fold 0 --retrieval-profile robust --output runs/ranker_data_robust_fold0
    if ($LASTEXITCODE -ne 0) { throw "새 검색 OOF 특징 생성 실패" }

    .\.venv\Scripts\python.exe -m portmatch transform-ranker-cache --transform token-phonetic --data runs/ranker_data_robust_fold0 --output runs/ranker_data_robust_token_phonetic_fold0
    if ($LASTEXITCODE -ne 0) { throw "이름 특징 변환 실패" }

    .\.venv\Scripts\python.exe -m portmatch train-ranker --data runs/ranker_data_robust_token_phonetic_fold0 --output artifacts/ranker_robust_token_phonetic_fold0 --exclude-features retrieval_tonnage_rank --rounds 300 --threads 6
    if ($LASTEXITCODE -ne 0) { throw "86개 순위 모델 학습 실패" }

    .\.venv\Scripts\python.exe -m portmatch compare-retrieval --baseline artifacts/ranker_token_phonetic_fold0 --profiles robust --experiment-model artifacts/ranker_robust_token_phonetic_fold0 --output runs/compare_robust_retrained_fold0
    if ($LASTEXITCODE -ne 0) { throw "재학습 모델 비교 실패" }
}
```

최초 검색 교체 분석 때는 특징 생성·학습을 실행하지 않았으며 사용자가 이후 완료했습니다. 이미 사용한 개발 fold의 후속 실험이며 독립 테스트는 아닙니다.

## 재학습 완료와 비교 재실행 — 2026-10-24 당시 오류 수정 기록

이 절은 비교 오류 수정 직후의 상태입니다. 이후 전체 비교를 완료했으며 [최종 분석과 결정](robust-retrained-fold0.md)을 따릅니다.

`artifacts/ranker_robust_token_phonetic_fold0`의 완료 메타데이터와 저장 검증 결과를 확인했습니다. 원본 입력의 한글 정답은 173/180, 비한글은 2,270/2,272, 가중 Top-1은 **97.2514%**이며 후보 재현율은 100%입니다. 기존 원본의 한글 175/180·가중 98.0291%보다 한글 정답 2행 순감, 가중 0.7778%p 하락했습니다. 개별 개선·신규 오답과 톤수 변형의 재학습 효과는 전체 비교 후 분석합니다. 이 단계에서 채택하거나 다른 fold로 확대하지 않습니다.

후속 `compare-retrieval`의 `Experimental memory differs from baseline training-only assets`는 **비교 도구의 오판**이었습니다. `joblib.hash`는 `frozenset`을 정렬하지 않아 서로 다른 Python 프로세스가 저장한 동일한 선박 집합에도 다른 해시를 줄 수 있습니다. 실제 두 모델의 호출부호·정규화 이름별 지지도, 별칭 데이터프레임의 값·행 순서·dtype, 훈련 행 수·선박 집합과 국적·선종 통계는 모두 같습니다. 원본 훈련 분할 9,770행·4,681척으로 사전과 범주 통계만 재구성해서도 두 모델과 일치했고 검증 1,170척과의 교집합은 없습니다.

비교기는 모든 학습 상태 필드를 실제 값으로 대조하도록 수정했습니다. 사전 항목·지지도·선박 집합·별칭 순서/형식·범주 통계가 달라지거나 알 수 없는 상태 필드가 생기면 계속 거부합니다. 입력·인덱스 파일 해시, 분할, 특징 순서와 학습 설정 검사도 유지합니다. 검색·특징 구현, 기존 캐시·저장 모델을 수정하지 않아 **특징 생성과 재학습은 필요 없습니다.**

수정 후 전체 회귀 테스트 **203개**가 통과했습니다. 다른 `PYTHONHASHSEED`의 별도 프로세스에서 같은 사전을 저장한 사례와 실제 사전 변경을 구분하는 테스트를 추가했습니다. 실제 저장 모델로 한글 4척·비한글 4척의 8행 × 5입력 × 3방법, **120회 비교**도 완료했습니다. baseline·재학습 모델 모두 원본 8행의 예측·후보 수·정답 순위가 각각의 저장 검증 결과와 일치합니다. 이 연결 점검은 전체 성능 평가가 아니며 로컬 근거는 `work/robust_compare_fix_smoke/`입니다.

오류 수정 당시에는 출력 폴더 생성 전 중단돼 `runs/compare_robust_retrained_fold0`가 없음을 확인했습니다. 아래 명령으로 비교를 재실행했고 현재는 완료됐으므로 반복하지 않습니다.

```powershell
cd C:\dacon\port
.\.venv\Scripts\python.exe -m portmatch compare-retrieval --baseline artifacts/ranker_token_phonetic_fold0 --profiles robust --experiment-model artifacts/ranker_robust_token_phonetic_fold0 --output runs/compare_robust_retrained_fold0
```

전체 2,452행 × 5입력 × 3방법(baseline / 고정 가중치+robust / 재학습 robust)을 평가합니다. 이전 검색 교체 비교와 새 모델 재학습 결과를 혼동하지 않습니다.
