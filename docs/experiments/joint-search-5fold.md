# 조합 증강과 한글 검색 확대: 전체 5-fold 결과

> 공개용 정리본: 실제 선박별 입력·정답·예측·점수와 행 식별자는 제외했다. 아래 성능표는 실제 실험의 집계 수치이며, 오류의 원리는 별도의 [가상 예시](../fictional-examples.md)로 설명한다.

2026-10-31, `runs/joint_search_v1_20261031`. 사용자가 VS Code에서 완료한 실행을 분석했다. **기존 최고 제출 모델의 교체는 보류한다.** 두 방법은 목표 복합 오류에서 각각 효과가 있고 함께 쓸 때 더 좋다. 그러나 새로 고정한 강한 톤수 축소 조건에서 반복적인 손실이 확인되어, 모든 입력에 적용할 후속 모델로 바로 채택하기는 어렵다.

현재 최고 Public **0.8424607623**은 사용자가 보고한 기존 robust·86개·GT 결측 증강 0.5의 **fold0** 점수다. 이번 표는 공개 데이터의 선박 분리 검증이며 새 Public 결과가 아니다. 모델·제출 ZIP을 교체하거나 생성·제출하지 않았다.

**비교의 기준**

`best`는 기존 최고 제출 **설정**으로 만든 각 fold 모델이다. `control`은 직전 실험의 증강 확대 모델(`expanded`, 어려운 오답 재학습 미적용)이다. `augmentation`은 이 대조군에서 조합 증강만 바꾼 모델, `retrieval`은 대조군 가중치를 그대로 두고 한글 후보만 추가한 방법, `both`는 조합 증강 가중치에 같은 후보 추가를 적용한 방법이다.

따라서 이번 변경의 독립적인 효과는 **조합 증강−대조군**, **검색 확대−대조군**으로 읽어야 한다. 기존 최고와의 차이에는 직전 증강 확대 효과도 포함된다. **기존 최고 가중치+새 검색만** 붙인 조합은 이번 실험에 없으므로 그 성능을 추정해 채택하지 않는다.

검증은 12,222행·5,851척, 한글 1,191행·비한글 11,031행이다. 16조건×5방법의 **977,760개 예측**을 전부 확인했다. 점수는 fold별 점수 평균이 아니라 전체 언어별 정답/분모를 합친 `0.7×한글 Top-1 + 0.3×비한글 Top-1`이다. 앞 12조건은 기존 회귀 검증, 마지막 4조건은 실행 전에 추가로 고정한 합성 오류다. 서로 발생 빈도가 알려지지 않은 조건을 임의로 평균하지 않는다.

- **조합 증강은 목표했던 오류에서 분명한 개선을 보였다.** 순서 교환+두 GT ×0.70에서 +13.0914%p, 두 GT ×1.25에서 +3.5428%p다. 새 2개 삭제+GT ×1.50에서도 +16.2676%p여서 기존 오류 한 조건에만 맞춘 결과는 아니다. ×0.70과 새 ×1.50은 5개 fold 모두 개선됐다.
- **모든 오류에 대한 강건성이 좋아진 것은 아니다.** 새 2개 삭제+GT ×0.55에서는 조합 증강만으로 −5.9289%p이며 5개 fold 모두 악화했다. 순서 교환만 −0.5551%p, 국적·선종 결측 −0.5290%p, 두 GT 결측 −0.5262%p도 점 추정상 손실이다. 뒤 세 조건은 구간에 0이 포함되므로 개선·악화를 확정적으로 일반화하지 않는다.
- **한글 검색 확대는 후보 누락 조건에서 효과가 있었다.** 기존 삭제+GT 결측 +2.1746%p, 순서 교환+GT ×0.70 +2.8212%p, 새 삭제+GT 결측 +1.2343%p다. 세 구간은 0보다 크다. 원본과 대부분의 단일 오류에서는 정답 후보가 이미 있어 추가 이득이 없다.
- **두 방법의 결합은 조건에 따라 상승 효과와 손실을 모두 보였다.** 순서 교환+GT ×0.70은 대조군 대비 +20.0267%p, 증강만 대비 +6.9353%p다. 상호작용도 +4.1142%p [2.1538, 6.3144]로 양수다. 새 ×1.50의 상호작용은 +1.2930%p [0.0647, 2.6507]지만 하한이 작고 다중 비교를 보정하지 않았다. 새 ×0.55는 상호작용 −1.7045%p [−2.8047, −0.8242]로 오히려 손실이 커진다.

**검색과 순위 선택을 나눠 본 원인**

기존 후보의 특징과 점수는 그대로 유지되고 한글에서만 256척을 더했다. 비한글의 예측은 검색 적용 전후 완전히 같다. 정답 후보 회복과 그 후보가 실제 1위가 되는 일은 다르다. 아래의 신규 오답은 원래 맞혔지만 추가 후보가 기존 정답을 밀어낸 경우다.

|---|---|---|---|---|---|
| 원본 | 0 | 0 | 0 | 0 | 0 |
| 이름 삭제+두 GT 결측 | 82 | 45 | 8 | 53 | 5 |

순서 교환+GT ×0.70의 한글 정답 후보 누락은 **314→124행**, 후보 재현율은 **73.6356→89.5886%**다. 회복된 190행 중 대조군은 53행만 최종 정답으로 선택하고 5행을 새로 틀린다. 조합 증강 모델은 **127행을 회복하고 9행을 새로 틀려 순 118행**을 더 맞힌다. 증강은 기존 후보 안에서의 선택을 개선하고, 검색은 이전에 불가능했던 정답을 추가해 서로 보완했다.

새 ×0.55는 다른 양상이다. 검색으로 한글 정답 후보 누락이 **329→272행**으로 줄지만, 조합 증강 모델은 회복 후보 57행 중 **3행만** 맞히고 기존 정답 **25행을 잃는다**. 이때 검색 추가 효과는 −1.2930%p다. 조합 증강 자체도 같은 후보 집합에서 한글 정답 **487→392**, 비한글 **9,499→9,372**로 떨어지므로 주된 신규 손실은 후보 검색 실패가 아니라 최종 순위 선택의 문제다.

훈련 톤수 배율은 .65/.80/1.20/1.35이고 검증의 .55/1.50은 들어 있지 않았다. **관측으로 확인되는 것은 더 큰 톤수 축소 방향에서의 순위 일반화 실패**다. 이름 오류와 GT 오차 범위를 동시에 바꾼 정책이므로 어느 구성 요소나 특징이 단독 원인인지까지 식별되지는 않는다. 추가 후보의 검색 점수 표현도 원래 학습 후보와 완전히 같지 않아, 이를 학습에서 경험하지 않은 것이 손실의 한 원인일 가능성은 있으나 이번 비교만으로 확정할 수 없다.

새 네 조건에서 이름 문자 2개가 실제 삭제된 행은 **11,623행(한글 881·비한글 10,742)**이다. 짧은 이름 등 **599행(한글 310·비한글 289)**은 이름을 유지했다. ×0.55의 이름 유지 한글 310행에서도 기존 최고→대조군→증강→둘 다 정답이 **289→247→219→215**다. 실제 삭제된 한글 881행은 **235→240→173→155**다. 따라서 손실을 문자 두 개 삭제만의 문제로 볼 수 없다. 모든 점수는 이 미변형 행까지 포함한 사전 정의 조건의 결과다.

**기존 최고 모델을 교체할지**

목표 복합 오류에서 `both`는 기존 최고 대비 **+16.4438%p**, 새 ×1.50에서 **+16.8008%p**다. 반면 새 ×0.55는 **−8.0205%p [−10.7206, −5.4139]**로 손실이 크고, 기존 최고 대비로도 5개 fold 모두 악화한다. 이 장단점을 숨겨진 오류 빈도를 모르는 상태에서 하나의 평균으로 상쇄할 수 없다.

실제 최고 제출이 fold0이므로 같은 외부 검증 fold0도 별도로 확인했다.

다음 우선순위는 .55 한 점에만 맞추기보다 넓은 톤수 과소·과대 범위와 이름 변형/미변형을 분리해 방금 발견한 퇴행을 막는 것이다. 기존 .55/.70/1.50은 이제 회귀 검증으로 유지하고, 새로운 합성 오류를 고정한 후 비교해야 한다. 검색 확대는 유지 가치가 있지만, 추가 후보를 포함한 학습·점수 표현의 정합성을 별도 요인으로 검증할 필요가 있다. 기존 최고 가중치에 검색만 붙이는 대조도 추가하면 재학습 없이 얻을 수 있는 효과를 직접 판단할 수 있다. 이 후속 실행은 이번 분석에서 시작하지 않았다.

교체 대상 14,954그룹 중 **14,547그룹(97.28%)**에 조합 증강이 실제 적용됐다. 정답 후보 누락 283그룹, 유효 조합 불가 124그룹은 원래 대조군 그룹을 유지했다. 적용 실패가 대부분이라 효과가 사라진 실험은 아니다. 이는 전체 원본의 97.28%라는 뜻이 아니며, 추가 증강 중 선택된 `dual_gt_noise` 그룹에 대한 비율이다. 후보 수·그룹 순서·원본/언어 질량·86열·300회 설정은 고정됐다. 새로 어려운 오답 재학습을 추가하지 않았다.

측정된 고유 한글 입력 7,570개에서 추가 검색·특징 처리 비용은 평균 **117.2ms**, 중앙값 **114.8ms**, 95백분위 **139.1ms**다. 공통 검색·특징 평균 167.7ms에 약 69.9%의 비용이 더해진다. 한글에는 매번 256척이 추가되고 비한글 추가 후보는 0이다. 캐시 재사용·여러 조건·병행 실행이 섞인 계측이며, 순위 모델 점수 계산을 포함한 실제 제출 ZIP 전체 소요 시간과 동일하지 않다.

실행 당시 보고서는 92,627개 추가 그룹·11,908,871개 후보 쌍을 검사하고, 교체하지 않은 78,080그룹의 값과 라벨 보존을 확인했다. 이번 분석에서는 **기존 보호 파일 7,764개, 새 증강 조각 1,449개, 새 native 모델 5개, 예측·로그·manifest 해시**를 다시 확인했다. 기존 12조건의 최고 설정·대조군 예측과 점수는 부모 실험과 정확히 일치한다. 전체 분모/분자·모든 쌍의 개선/퇴행 수·상호작용을 저장 예측으로 재계산했고, 후보 누락 비증가·비한글 예측 불변도 확인했다.

공통 후보 86열·점수 동일성은 해시가 고정된 실행 코드의 계산별 검사와 완료 기록으로 확인했다. 이번 감사에서 모든 검색·특징 생성·학습을 다시 실행하지 않았다. 5,000회 구간도 완료된 보고서 값을 읽었다. 구현 당시 관련 31개 테스트 통과 기록은 유지하며, 분석·문서 추가만 한 이번 작업에서 전체 테스트는 재실행하지 않았다. 기존 모델과 제출물은 보존됐다.
