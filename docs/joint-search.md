# 이름 오류+틀린 톤수 증강 × 한글 후보 검색 확장

2026-10-31 실제 데이터 전체5-fold 학습·평가·분석 완료. `runs/joint_search_v1_20261031/`의 12,222행·977,760개 예측을 확인했다. 순서 교환+두 GT×0.70에서 대조군 대비 조합 증강+13.0914%p·검색 확대+2.8212%p·동시 적용+20.0267%p다. 반면 새 문자2개 삭제+두 GT×0.55에서 동시 적용은 대조군 대비−7.2220%p, 기존 최고 대비−8.0205%p로 악화했다. **기존 최고 Public0.8424607623 모델은 유지한다.** [전체 결과·효과 분리·교체 판단](experiments/joint-search-5fold.md).

기존 보호 파일7,764개와 새 증강 조각1,449개·모델5개·예측 해시를 재확인했다. 기존 모델·제출물은 보존했으며 새 제출은 하지 않았다. 아래 명령은 실행 기록과 재현 안내이며, 완료된 실험을 다시 학습할 필요는 없다.

## VS Code 실행

PowerShell 터미널에서 다음 명령을 실행한다. 처음에는 현재 코드·설정·입력 파일을 고정하고 보호 파일 해시를 기록한 뒤, 외부 선박5-fold 학습·평가·결과 검증을 모두 수행한다.

```powershell
cd C:\dacon\port
.\.venv\Scripts\python.exe scripts\run_joint_search_study.py --parent runs\compound_v1_20261030 --output runs\joint_search_v1_20261031 --workers 2
```

최대2개 fold를 병행하지만 큰 학습 행렬 생성과 최종 학습은 파일 잠금으로 한 번에 하나만 실행한다. 메모리를 더 아끼려면 `--workers 1`을 사용한다. 각 fold에는 새 모델1개만 학습하며, 기존 최고 모델과 직전 증강 모델은 재학습하지 않는다. 새 보조 모델이나 어려운 오답 선택은 추가하지 않는다.

진행 상태만 읽는 명령:

```powershell
.\.venv\Scripts\python.exe scripts\run_joint_search_study.py --output runs\joint_search_v1_20261031 --status
```

`initialized: false`는 아직 실행하지 않은 정상 상태다. `Ctrl+C`는 실행 중인 자식 학습·평가도 중단한다. 같은 실행 명령을 다시 쓰면 완료된 fold는 건너뛰고, 미완료 fold의 폴더·로그는 실험 내부의 `interrupted_날짜_시간/`에 보존한 뒤 그 fold를 처음부터 실행한다. 부분 생성된 조각부터 이어 붙이지 않는다. 같은 runner의 중복 실행은 잠금으로 막는다.

고정 이후 구현 파일이나 부모 실험·캐시가 바뀌면 실행을 거부한다. 이를 무시하거나 프로토콜의 해시를 손으로 갱신하지 않고, 변경된 설정은 새 출력 폴더에 별도로 고정한다. 현재 최고 제출을 자동 교체하거나 제출 ZIP을 만들지 않는다.

## 효과를 분리하는 비교

직전 결과에서 효과가 확인된 `compound_v1`의 `expanded`를 대조군으로 쓴다. 기존 최고 Public0.8424607623(사용자 보고) 설정도 별도 기준으로 포함한다.

| 결과 이름 | 학습 모델 | 추론 검색 | 역할 |
|---|---|---|---|
| `best` | 기존 robust·86개·GT 결측0.5 | 기존 검색 | 최고 제출 설정의 fold별 기준 |
| `control` | 직전 증강 확대 모델 | 기존 검색 | 2×2 비교의 기준 |
| `augmentation` | 이름 오류+틀린 톤수 조합으로 일부 증강 교체 | 기존 검색 | 증강 변경만 |
| `retrieval` | `control`과 같은 가중치 | 한글 후보 추가 | 검색 변경만 |
| `both` | `augmentation`과 같은 가중치 | 한글 후보 추가 | 두 변경 함께 |

- 증강 효과: `augmentation − control`.
- 검색 효과: `retrieval − control`.
- 조합 증강 상태에서의 검색 효과: `both − augmentation`.
- 새 검색 상태에서의 증강 효과: `both − retrieval`.
- 상호작용: `both − augmentation − retrieval + control`.
- 네 방법 각각을 `best`와도 비교한다. 최종 후보 선택과 Public 점수 상승은 자동으로 판단하지 않는다.

새 검색은 추론 후보 확장이다. 새 검색으로 다시 훈련하는 변경까지 섞지 않는다. 검색 변경에는 새 후보를 고르는 방식과 그 새 후보의 검색 점수를 86열에 기록하는 정책이 포함된다. 기존 후보의 특징을 재보정하는 실험은 아니다.

## 조합 증강

원본·GT 결측 학습 캐시와 직전 `expanded`의 추가 그룹을 재사용한다. 추가 그룹 중 **기존 `dual_gt_noise` 자리만** 다음 조합으로 바꾼다.

- 이름 문자1개 삭제 또는 인접 문자 순서 교환.
- 사용 가능한 양수 GT를 같은 배율 `.65 / .80 / 1.20 / 1.35` 중 하나로 변형. 결측을 만들어 넣지 않는다.
- 원본 입력6필드·관점(vessel/row)·seed20261031의 해시로 선택한다. 정답·sample_id·arrival_year나 다른 질의는 선택에 사용하지 않는다.
- 숫자 시퀀스, 로마 숫자 토큰, 한글/비한글 구분을 보존한다.

각 그룹은 원래 내부 OOF 분할의 검색·범주 통계로 다시 만든다. 외부 검증 선박과 내부 검증 행은 fitting에서 제외하며, 내부 vessel 관점에서는 해당 선박 전체를 제외한다. 내부 row 관점은 기존 실험의 정의를 유지한다.

다음 경우에는 원래 대조군의 그룹을 그대로 남긴다.

1. 이름과 톤수가 모두 바뀌는 유효한 조합을 만들 수 없음.
2. 새 입력의 검색 후보에 정답이 없음.
3. 샘플링된 후보 수가 원래 그룹과 다름.

정답 후보를 강제로 삽입하지 않는다. 교체 성공·실패 원인과 적용된 이름 오류·톤수 배율을 `foldN/joint_log.csv`에 기록한다. 적용률이 낮으면 개선 효과도 제한될 수 있으므로 `training_effective_groups.csv`와 함께 해석한다.

**대조군과 그룹 순서·수, 그룹별 후보 수, 원본별·언어별 질량,86열·300회 설정이 같다.** 교체하지 않은 추가 그룹의 후보·특징·라벨도 같다. 일반적인 원본의 질량은 직전 실험과 같은 원본0.5·기존GT마스크0.25·추가증강0.25이며 기존 예외 정책도 그대로다.

이 비교는 이름 오류와 더 넓은 GT 오차를 함께 넣는 **증강 정책의 효과**다. 이름 오류 자체와 톤수 오차 강도의 인과 효과를 별도로 식별하는 대조는 아니며, 조합 증강을 모든 원본에 적용했다고 해석하지 않는다.

## 한글 후보 검색 확장

추가 검색은 고정 카탈로그의 이름만으로 만든다. 훈련 라벨·검증 입력·정답 이름 사전·다른 질의를 인덱스에 넣지 않는다. 기존 이름 문맥/모음 표현을 이용해 다음 결과를 합친다.

- 문자1~2개 단위 TF-IDF 검색: 상위512척.
- 인접 문자 교환을 고려하는 OSA 편집 유사도: 상위256척.
- 각 검색은 이름 표현을 선박별 최댓값으로 먼저 합쳐 중복 표현이 후보 예산을 독점하지 않게 한다.
- 기존 후보를 제외한 뒤 점수와 vessel_id로 결정적으로 정렬해 **최대256척만 추가**한다. GT 조건으로 걸러내지 않는다.

비한글 입력은 기존 후보를 그대로 사용한다. 한글도 기존 후보를 제거하지 않는다. 기존 후보의 검색 점수·순위·채널 수와 전체86열을 그대로 유지하고, 최종 모델 점수도 같은지 계산마다 확인한다.

새 후보만 `phonetic_hit=1`, `phonetic_score=두 새 검색 점수의 최댓값`, `channel_count=1`로 기록한다. 새 순위는 기존 phonetic_rank 최댓값 다음부터 부여한다. 새 후보 점수의 의미는 기존 검색 경로와 완전히 같다고 가정하지 않는다. 따라서 정답 후보 회복뿐 아니라 추가 오답 후보가 기존 정답을 밀어내는 손실도 따로 보고한다.

후보 재현율은 감소하지 않아야 하지만 최종 정확도는 하락할 수 있다. 기존 후보 안의 순서는 바뀌지 않으므로 검색만 바꾼 경우의 회복은 새로 찾은 정답에서만 생겨야 한다. 이 조건도 저장 결과 감사에서 검사한다.

## 검증 조건과 산출물

기존12조건은 회귀 검증으로 유지하고, 다음4조건을 사전 고정한다.

1. 새로운 고정 위치 규칙으로 이름 문자2개 삭제.
2. 같은 삭제+두 GT 결측.
3. 같은 삭제+두 GT×0.55.
4. 같은 삭제+두 GT×1.50.

문자2개 삭제와 두 배율은 이번 학습 증강에 넣지 않는다. 짧은 이름 등에서2개 삭제가 불가능하면 이름을 원래대로 유지하며, 결과의 `name_changed_queries`·`two_letter_deletions`로 실제 적용 수를 보고한다. `fresh`는 새로 고정한 합성 오류라는 뜻이며, 동일 공개 선박에서 만든 독립적이지 않은 검증이다. 기존12조건과 섞어 임의 평균하거나 Public 예상 점수로 해석하지 않는다.

전체 완료 시 12,222행 × 16조건 × 5방법 = **977,760개 예측**이다. 모든 조건에서 한글0.7·비한글0.3 가중 Top1과 언어별 정답/분모, 후보 재현율, 개선/신규 오답 행·선박 수를 기록한다. 선박 단위 paired bootstrap5,000회(seed20261031)로 각 효과와 상호작용의95% 구간을 계산한다. 반복 모델 선택·다중 비교·숨겨진 데이터의 분포 변화는 이 구간으로 보정되지 않는다.

| 파일 | 내용 |
|---|---|
| `metrics.csv` | 16조건·5방법 성능, 언어별 분모, 후보 수와 실제 이름 변형 수 |
| `paired_changes.csv` | 증강·검색·동시 적용 및 최고 모델 대비9개 쌍의 개선/퇴행 |
| `interactions.csv` | 증강과 검색 사이 상호작용 |
| `retrieval_effects.csv` | 회복/손실 후보, 회복 후 최종 정답 수, 추가 오답 후보로 인한 퇴행 |
| `confidence_intervals.json` | 쌍별 효과와 상호작용의 선박 단위95% 구간 |
| `changed_rows.csv` | 실제 바뀐 예측과 선박명 |
| `training_effective_groups.csv` | fold별 조합 증강 적용 수와 실패 이유 |
| `analysis_audit.json` | 분할·보존·정답 후보·동일 그룹 및 교체하지 않은 특징의 검사 |
| `foldN/timings.csv` | 고유 입력별 공통 처리 시간·추가 검색/특징 비용·추가 후보 수 |

추론은 후보와 특징을 공유하고 같은 입력 계산을 재사용한다. 기록 시간은 제출 ZIP의 전체 실행 시간과 같지 않다. 새 모델은 `foldN/joint/`에 저장하고, `JointSearchMatcher(root, fold, arm)`으로 해당 기존 인덱스에 연결해 복원한다. 모델 폴더만으로 독립적인 제출 ZIP이 되지는 않는다.

## 기능 검증

신규10개 테스트와 기존 복합 오류8개·robust 검색13개, 총31개 관련 테스트를 통과했다. 합성 통합 검증은 기존 부모 실험 생성→새 프로토콜 고정→조합 증강 학습→5방법·16조건 평가→보존 감사→터미널 runner의 완료 단계 재사용까지 실행한다. 숫자/언어 보존, 정답 후보 누락·후보 예산 변경 시 복구, 공통86열·점수 불변, 모델 복원·순서 독립성, 파일 변조 검출도 확인한다.

```powershell
$env:TEMP='C:\dacon\port\work\test_tmp'
$env:TMP=$env:TEMP
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_joint_search.py -v
```

합성 테스트 정확도는 실제 성능 결과로 사용하지 않는다. 실제 실행의 전체5-fold 결과는 [완료 보고서](experiments/joint-search-5fold.md)에 정리했다. 이번 결과 분석에서는 장시간 학습·검색·전체 테스트를 다시 실행하지 않았다.
