# 가상 예시로 이해하는 선박 매칭 오류

[프로젝트 개요](../README.md) · [실제 실험 집계](experiment-evidence.md)

**이 문서의 이름·식별자·톤수·점수는 설명을 위해 새로 만든 가상 값이다. 실제 데이터 행을 익명화한 대응표나 모델 실행 결과가 아니다.** 실제 성능은 별도로 공개한 집계 결과에서 확인한다.

## 1. 정답이 후보에 들어오지 않는 검색 오류

가상의 입력 이름이 `데모 루멘7`이고 정답 카탈로그 이름이 `DEMO LUMEN 7`이라고 가정한다. 영문 문자 일치만으로 검색하면 한글 음차를 연결하지 못해 정답이 후보에서 빠질 수 있다.

| 단계 | 설명용 상황 |
|---|---|
| 입력 | `데모 루멘7`, 호출부호 없음 |
| 문자 검색 후보 | `DEMO LUNAR 7`만 포함 |
| 정답 | `DEMO LUMEN 7`이 후보에 없음 |
| 개선 방향 | 정규화·음차·토큰 검색을 추가해 정답이 검색될 가능성을 높임 |

이 경우 후보 안의 순위만 바꾸어도 정답을 선택할 수 없다. 그래서 정답 후보 포함 여부와 최종 1위 정답률을 따로 측정했다. 검색 후보를 늘리면 비슷한 오답도 추가되므로 후보 수 증가만으로 정확도 향상을 보장하지 않는다.

## 2. 정답 후보가 있어도 틀린 톤수에 이끌리는 순위 오류

이번에는 정답이 검색 후보에 있지만 입력 톤수가 잘못 기록된 상황이다.

| 구분 | 가상 이름 | 가상 총톤수 |
|---|---|---:|
| 입력 | `데모 루멘7` | 7,700 |
| 정답 후보 A | `DEMO LUMEN 7` | 14,000 |
| 오답 후보 B | `DEMO LUMEN 9` | 7,700 |

입력 톤수는 정답의 **×0.55**이고, 오답의 톤수와 우연히 같다. 톤수 일치를 과하게 신뢰하면 후보 B를 고를 수 있다. 이 문제를 다루기 위해 이름 오류와 톤수 오차를 함께 적용한 학습 예제를 만들고, 혼동하기 쉬운 오답을 학습에 반영했다.

이 표는 오류의 구조를 보여주기 위한 가정이다. 실제 focused_search가 위 가상 입력을 맞혔다는 주장이 아니다.

## 3. 특정 조건의 개선이 다른 조건의 유지를 뜻하지 않는 이유

같은 가상 정답의 톤수 14,000에 ×0.70을 적용하면 9,800, ×1.50을 적용하면 21,000이 된다. 이름도 동시에 훼손하면 조건마다 경쟁하는 오답이 달라질 수 있다.

따라서 한 조건의 오답을 더 학습한 뒤에는 해당 조건뿐 아니라 **원본·×0.55·×1.50과 이름 단독 오류**도 함께 비교해야 한다. 실제 프로젝트에서는 마지막 동시 보강이 ×0.70에서 개선됐지만 ×0.55와 원본에서 손실이 발생해 최종 모델을 교체하지 않았다. 정확한 변화량과 비교 범위는 [실험 근거](experiment-evidence.md)에 있다.

## 공개 문서를 읽는 기준

- 이 문서와 README의 설명용 입력은 가상 예시다.
- 실험 문서의 조건별 정확도·정답 수·시간은 완료된 실험의 집계 기록이다.
- 실제 선박 이름과 정답·오답의 연결, 개별 후보 점수·특징 벡터, 학습 행 식별자는 공개본에서 제외했다.
- 실제 데이터로부터 만든 사전·통계·모델 가중치와 제출 ZIP도 포함하지 않는다.
