## 학습 변경

톤수 배율은 **0.4 / 0.5 / 0.625 / 0.8 / 1.25 / 1.6 / 2.0 / 2.5**로 고정했다. 과소·과대 배율을 역수 쌍으로 구성하고, 이름은 유지·문자1개 삭제·문자2개 삭제·인접 문자 교환 중 하나를 사용한다. 특히 ×0.55 한 값만 추가해 해당 검증에 맞추는 방식은 사용하지 않는다.

각 원본의 vessel/row 내부 OOF 관점마다 하나의 조합을 결정한다. 선택은 입력6필드·관점·seed20261101의 해시를 사용하며 정답·sample_id·연도는 선택에 영향을 주지 않는다. 숫자 시퀀스·로마 숫자 토큰·한글 여부를 보존하고, 짧은 이름의 삭제가 불가능하면 이름을 유지한다. 유효한 양수 GT만 변형하며 GT가 모두 무효/결측이면 추가 예제를 건너뛴다. 이름 유지와 실제 변형 수는 별도 기록한다.

검색·범주 통계는 각 내부 OOF fitting에서 다시 만든다. 외부 검증 선박과 내부 검증 행을 제외하며, vessel 관점에서는 내부 검증 선박 전체를 제외한다. 카탈로그 전체 이름을 사용하는 추가 검색에는 질의나 라벨을 학습시키지 않는다.

**기존 원본 캐시와 직전 조합 증강 그룹을 모두 그대로 다시 사용한다.** 이전 예제의 특징·후보·라벨을 바꾸거나 삭제하지 않는다. 원본 그룹의 원본별 `query_mass`도 그대로 유지한다. 새 예제가 있는 원본에서 기존 비원본 증강 질량의40%를 옮기되, 원본당 최대0.20을 새 예제에 배분한다. 전형적인 질량 구성은 다음과 같다.

| 학습 예제 | 직전 모델 | 새 모델 |
|---|---:|---:|

이는 원본별 상대 질량이다. 기존 예외 원본은 실제 비원본 질량에 맞춰 적은 양을 배분하며, 추가 예제를 만들지 못한 원본의 질량은 그대로 유지한다. 원본밖에 없어 옮길 증강 질량이 없는 경우 추가 예제를 건너뛴다. 원본별 합계1·언어별 가중치·86개 특징·LightGBM300회 설정은 유지한다. 원본 예제의 비중 보존이 원본 정확도 보장을 뜻하지는 않는다.

새 예제는 실제 추론과 같은 **기존 후보+한글 추가 후보**에서 만든다. 기존 후보에 없었으나 추가 검색이 정답을 찾아준 경우도 학습한다. 전체 후보에 정답이 없으면 두 모델에서 함께 건너뛰고 정답을 임의로 삽입하지 않는다. 이 추가 검색은 기존 후보의86열과 점수를 보존하는 직전 구현을 그대로 쓴다.

| 새 모델 | 추가 예제의 오답 후보 선택 |
|---|---|
| `broad` | 기존의 이름·음차·톤수·범주 기반 heuristic 샘플링 |
| `focused` | 추가 검색으로 들어온 오답 중 최대32개를 이름 문맥·모음·음차·톤수 근접도 순위로 우선 선택하고 나머지를 기존 샘플로 채움 |

`focused`의 긍정/부정 후보 수는 `broad`와 같다. 정답을 제외하는 데만 라벨을 사용하고, 오답 점수는 OOF에서 계산된 특징으로 결정한다. 외부 검증의 오답 목록이나 학습된 교사 모델의 점수를 사용하지 않는다. 실제 추가 오답 노출 수와 선택이 달라진 그룹 수를 결과에 기록한다.

`broad`에는 **톤수/이름 증강 확대와 추가 검색 후보를 학습에 반영하는 변경이 함께** 들어 있다. 이 둘 자체의 효과를 따로 식별하는 실험은 아니다. `focused−broad`는 같은 추가 예제에서 오답 후보 선택 정책의 추가 효과를 분리한다.

| `focused_search` | 이번 추가 오답 노출 보강 모델 | 한글 추가 검색 |

직전16조건의 최고 모델·직전 조합 증강·직전 동시 적용 예측을 부모 실행과 정확히 대조한다. 모든 방법의 검증 행은 같고, 같은 검색을 쓰는 방법의 후보 집합은 같다. 비한글은 검색 추가 전후 예측이 같아야 한다.

주요 목표는 기존 `fresh_double_delete_gt_x0_55` 조건의 개선이다. 이 조건은 이제 알려진 오류이므로 **회귀 검증**으로 취급한다. 그 밖의 기존15조건을 모두 유지 검증에 포함한다. 원본, 순서 교환+두 GT×0.70, 새2개 삭제+두 GT×1.50, 이름 삭제+GT 결측의 기존 이득을 특별히 확인한다.

새 모델과 같은 검색을 쓰는 직전 모델을 비교한다. ×0.55 개선값과95% 구간을 표시하고, 나머지15조건은 각각 **−0.25%p**를 넘는 하락이 있는지 보고한다. 이는 실험 전에 정한 개발상의 허용 손실 기준이며 대회 규칙이 아니다. 점 추정으로 통과했는지와95% 구간 하한까지 이 기준을 만족하는지는 따로 표시한다. fold0 손실도 별도로 기록한다. 기존 최고 설정과의4개 비교를 포함해 총12쌍을 제공하며, 어느 기준을 통과해도 자동 교체하지 않는다.

기존에 보지 않은 합성 입력은 다음4조건을 추가한다.

1. 이름 유지+두 GT×0.45.
2. 새로운 위치 규칙의 문자2개 삭제+두 GT×0.45.
3. 이름 유지+두 GT×1.80.
4. 같은 새 삭제+두 GT×1.80.

0.45와1.80은 이번 학습 배율에 없고, 새 삭제 규칙은 이전 검증 위치와 다르다. 동일 공개 선박을 이용한 합성 검증이며 독립적인 숨겨진 평가 데이터는 아니다. 기존16조건과 임의 평균하거나 Public 예상 점수로 해석하지 않는다. 짧은 이름 등 실제2개 삭제가 안 된 행도 별도로 집계한다.

## 구현 검증과 보존

새로운11개 테스트와 직전 실험·검색31개 테스트, 총 **42개 테스트**를 통과했다. 합성 데이터로 부모 실험부터 새 모델2개 학습, 7방법·20조건·840개 예측, 분석 보고서, 저장 모델 복원, 입력 순서·라벨·ID·연도 독립성, 완료 fold 재사용을 확인했다. 수치·로마 숫자·언어 보존, 원본 질량 유지, 동일 후보 예산, 실제 검색으로 회복한 정답의 사용, 후보 누락 시 임의 삽입 방지, 파일 변조 거부도 검증했다.

구현 당시 실행 전 점검에서는 기존 보호 파일7,764개와 직전 모델5개·추가 증강 조각1,449개를 확인했다. 이후 사용자가 실제 실행을 완료했고, 결과 분석에서 새 프로토콜의 보호 파일9,296개·새 fold 파일1,502개·전체 예측과 집계를 재확인했다. 기존 모델과 제출물은 바뀌지 않았다. 이번 분석에서는 장시간 학습·검색이나 전체 테스트를 다시 실행하지 않았다.
